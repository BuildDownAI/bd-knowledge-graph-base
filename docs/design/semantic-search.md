# Design spec: lightweight semantic search over the KG

**Status:** approved design · **Date:** 2026-07-29 · Tracking issue: an internal tracker issue

Adds paraphrase-tolerant retrieval to the KG without turning it into a RAG blob.
The existing `kg_search` is **lexical** (whole-token / phrase match over titles and
topic tags), so `dedup` hits but `dedup TTL` and paraphrases like *"prevent
re-dispatching a torn-down issue"* miss. This adds a vector layer that catches
those — as a small **index into the graph**, not a second copy of the corpus.

## Guiding principle: vectors are pointers, not content

The graph already stores and structures every learning/decision/issue, with
provenance. So the vector layer only has to answer *"which node does this
paraphrased query point at?"* — once it lands on a node, the existing tools
(`kg_neighbors`, `kg_provenance`, the node's stored `detail`/`fix`) return the real
content deterministically. We therefore embed **one compact "index card" per
node**, never full bodies.

## Scope (what gets an index card)

Nodes embedded — **Learnings, Decisions, Issues** ("scope B"):

| Node type | Index card = |
|---|---|
| `kg:Learning` | `title` + `kg:tagged` topic labels + `kg:fix` snippet (already ≤400 chars) |
| `kg:Decision` | `title` + `kg:detail` snippet (first ~400 chars) |
| `kg:Issue` | `title` + non-lifecycle `kg:label`s + `kg:description` snippet (first ~400 chars) |

~300–500 cards total → ~300–500 small vectors.

## Non-goals (deliberately out of scope)

- **No full-corpus embedding** — no full learning/decision bodies, no full docs.
- **No document chunking** — the sprawling, heavy part of normal RAG; skipped entirely.
- **No vector database** (FAISS / sqlite-vec / Stardog vectors) — YAGNI at this scale.
- **No hybrid ranking** with `kg_search` in v1 — kept as a separate tool; revisit later.
- **No write-back / online re-embedding** — build is an offline batch step.

## Architecture

Three pieces, each independently testable:

### 1. Build step — `kg_ingest/embed.py` (decoupled from core ingest)

`python -m kg_ingest.embed` reads `out/graph.trig`, builds the index cards via
SPARQL over the three node types, embeds them with fastembed, and writes the
sidecar `out/embeddings.npz`. Core `kg_ingest.cli` stays dependency-light and
offline — fastembed is only imported here, so semantic search is opt-in. An
optional `cli.py --embed` flag chains this after a normal ingest.

**Model:** fastembed, pinned to **`BAAI/bge-small-en-v1.5`** (384-dim, ONNX, no
PyTorch; ~130 MB model cached once on first run — the only step needing network).
The model name is a module constant so it is trivially swappable.

**Sidecar files** (both gitignored, written together):
- `out/embeddings.npz` (numpy `savez`) — parallel arrays: `vectors` (float32
  `[N, 384]`, L2-normalized at build time) + `iris` / `types` / `titles` /
  `snippets` (`[N]` string arrays) + `meta` (JSON string: `{model, dim, count,
  built_from_quads, card_fields}` for the load-time model/dim guard).
- `out/embeddings.meta.json` — the same `meta` object as **plain JSON**, so
  `snapshot.py` can add the digest line **without importing numpy** (it stays
  fastembed/numpy-free; only `embed.py` and `semantic.py` touch the `.npz`).

### 2. Query function — `kg_query/semantic.py`

`semantic_search(query, limit) -> dict`. Loads the sidecar once into a
module-level singleton (mirrors `store()` in `server.py`), embeds the query with
the same pinned model, computes cosine similarity as a single normalized
matrix–vector product, and returns the top-k. Cosine over ~500 rows is a
sub-millisecond numpy `@`, so **no ANN index**.

Return shape mirrors `kg_search` for consistency:
```json
{ "query": "...", "model": "BAAI/bge-small-en-v1.5", "count": N,
  "results": [ { "iri": "...", "type": "Learning", "title": "...",
                 "snippet": "...", "score": 0.83 } ] }
```

### 3. MCP tool — `kg_semantic_search(query, limit=10)` in `server.py`

A 5th read-only tool alongside the four existing ones, delegating to
`semantic.semantic_search`. Docstring steers agents to it for paraphrased /
conceptual queries and notes that `kg_search` remains the fast exact-term path.
The lexical `kg_search` is left untouched.

## Data flow

```
BUILD (offline):  graph.trig → SPARQL cards → fastembed → normalize → out/embeddings.npz
QUERY (serving):  query → fastembed(query) → cosine top-k over vectors → [{iri,type,title,snippet,score}]
                  → agent follows kg_neighbors / kg_provenance for full content
```

## Storage & git

- `out/embeddings.npz` is a derived binary → **gitignored** (all of `out/` already
  is). Also avoids cross-machine float noise. Regenerated by the build step.
- `snapshot/digest.md` gains one deterministic line — `model`, `dim`, `count` —
  so the vector layer's presence and shape are reviewable without committing the
  blob. `kg_ingest/snapshot.py` reads `out/embeddings.meta.json` (plain JSON, no
  numpy) if present; absent → the line is omitted, no error. `count` is stable
  data, not a timestamp, so the line stays diff-friendly.

## Error handling

- **Sidecar missing** (semantic search never built): the tool returns
  `{error: "no embeddings index — run `python -m kg_ingest.embed`", results: []}`
  rather than raising, so the other four tools are unaffected.
- **Model/dim mismatch** between sidecar `meta` and the query-time model: fail
  loud with a clear message (stale sidecar → rebuild).
- **First-run model download** needs network; documented in README. Once cached,
  fully offline.

## Determinism & provenance

fastembed with a pinned model is deterministic per input on a given platform
(tiny cross-platform float differences don't matter — the sidecar is gitignored,
and top-k ordering is stable for this corpus). The `meta.built_from_quads` and
`model` fields record what produced the index, consistent with the KG's
provenance ethos.

## Testing — `tests/test_semantic.py`

Standalone assert script (repo convention; no pytest):
1. Build a tiny in-memory fixture graph with a dedup-TTL learning + an unrelated
   learning; run the embed + search path.
2. Assert a paraphrased query (*"stop re-dispatching a torn-down issue"*) ranks
   the dedup-TTL learning **first**, above the unrelated node.
3. Assert the missing-sidecar path returns the friendly error, not an exception.

Gated behind `fastembed` being importable so the core suite still runs without it.

## Dependencies

Add `fastembed>=0.3` to `requirements.txt` — it brings `numpy` and `onnxruntime`
transitively. `embed.py` and `semantic.py` import numpy; `snapshot.py` stays
numpy-free (reads the plain-JSON meta). Core `kg_ingest.cli` never imports
fastembed, so an install without it still builds/serves the graph — only
`kg_semantic_search` is unavailable.

## Rollout / usage

```bash
./.venv/bin/pip install -r requirements.txt      # pulls fastembed
./.venv/bin/python -m kg_ingest.embed            # build out/embeddings.npz (first run downloads model)
# restart the MCP client so the server loads the sidecar; kg_semantic_search goes live
```

## Future (explicitly deferred)

- **Hybrid** `kg_search` (lexical ∪ vector, merged/re-ranked) once we see how the
  separate tools perform.
- **Broader scope** (PRs/files/docs cards) if recall gaps appear.
- **model2vec** as an even-lighter swap if fastembed's footprint matters.
